    EXP-002: MediaPipe Hands → Unitree G1 Data Pipeline¶

    Owner: Tushar Vaidya
    Start Date: 2026-05-22
    Last Updated: 2026-05-22
    Status: Active

    Goal¶

    Build a data pipeline that takes egocentric or third-person video of human hands, extracts 3D hand landmarks using MediaPipe Hands, and converts them into joint-angle commands usable as training data for the Unitree G1 robot — formatted as LeRobot v2 (parquet + meta) compatible with GR00T finetuning.

    Hypothesis¶

    MediaPipe's multi_hand_world_landmarks (real-world 3D metres, 21 joints per hand) combined with per-joint inverse kinematics can produce retargeted hand trajectories close enough to the Unitree G1's hand action space to serve as usable imitation learning data — without requiring an expensive MoCap suit or glove-based tracker.

    Background¶

    See Motion Retargeting for Humanoids for the full theoretical context. This experiment is a kinematic retargeting pipeline:

    Egocentric / third-person video
        ↓
MediaPipe Hands (21 landmarks × 2 hands, world-space metres)
        ↓
Coordinate frame alignment (camera → robot base frame)
        ↓
IK / joint-angle regression (landmark positions → Unitree G1 DOFs)
        ↓
Contact & limit filtering (joint limits, self-collision check)
        ↓
LeRobot v2 parquet output  →  GR00T finetuning / SONIC tracking

    MediaPipe Hands: What We Get¶

    Output field Description Units
    multi_hand_landmarks 21 landmarks per hand, (x, y, z) Normalized [0,1] image space
    multi_hand_world_landmarks Same 21 points, metric Metres, centred at hand geometric centre
    multi_handedness Left / Right + confidence —

    21 landmark indices (per hand):

    Index Joint Index Joint
    0 WRIST 11 MIDDLE_PIP
    1 THUMB_CMC 12 MIDDLE_DIP
    2 THUMB_MCP 13 MIDDLE_TIP
    3 THUMB_IP 14 RING_MCP
    4 THUMB_TIP 15 RING_PIP
    5 INDEX_MCP 16 RING_DIP
    6 INDEX_PIP 17 RING_TIP
    7 INDEX_DIP 18 PINKY_MCP
    8 INDEX_TIP 19 PINKY_PIP
    9 MIDDLE_MCP 20 PINKY_DIP / TIP
    10 — — —

    Handedness mirror caveat

    MediaPipe determines Left/Right assuming the input image is horizontally flipped (front-facing / selfie camera). For egocentric or side-mounted cameras with no flip, handedness labels will be inverted. Must correct before mapping to robot left/right arm.

    Robot & Target Format¶

    Field Value
    Robot Unitree G1 (humanoid)
    Embodiment tag UNITREE_G1
    Target action dims 7 per arm (6 DOF arm + 1 gripper)
    Output format LeRobot v2 — parquet + meta/modality.json
    Codebase version v2.1
    FPS 30 Hz (match MediaPipe input)

    Pipeline Implementation Plan¶

    Step 1 — MediaPipe extraction¶

    import cv2
import mediapipe as mp
import numpy as np

mp_hands = mp.solutions.hands

def extract_landmarks(video_path: str, fps_target: int = 30):
    cap = cv2.VideoCapture(video_path)
    with mp_hands.Hands(
        static_image_mode=False,
        max_num_hands=2,
        model_complexity=1,           # higher accuracy
        min_detection_confidence=0.7,
        min_tracking_confidence=0.5,
    ) as hands:
        frames = []
        while cap.isOpened():
            ret, frame = cap.read()
            if not ret:
                break
            # NOTE: do NOT flip for egocentric / side cameras
            results = hands.process(cv2.cvtColor(frame, cv2.COLOR_BGR2RGB))
            frames.append(results)
        cap.release()
    return frames

    Step 2 — Coordinate frame alignment¶

    # MediaPipe world landmarks are in camera frame, centred at hand geometric centre.
# Must transform to robot base frame using camera extrinsics T_cam_base.

def to_robot_frame(landmark_world, T_cam_base: np.ndarray) -> np.ndarray:
    """landmark_world: (21, 3) in camera frame → (21, 3) in robot base frame"""
    pts_h = np.hstack([landmark_world, np.ones((21, 1))])  # homogeneous
    return (T_cam_base @ pts_h.T).T[:, :3]

    Step 3 — IK / joint-angle mapping¶

    Two candidate approaches — to be benchmarked in this experiment:

    Compute finger joint angles analytically from consecutive landmark vectors.

    def finger_angle(a, b, c) -> float:
    """Angle at joint b given three landmark positions."""
    v1 = a - b
    v2 = c - b
    cos_a = np.dot(v1, v2) / (np.linalg.norm(v1) * np.linalg.norm(v2) + 1e-8)
    return float(np.arccos(np.clip(cos_a, -1, 1)))

    Pros: Fast, interpretable, no training needed
    Cons: Does not account for robot joint limits or DOF mismatch

    Train a small MLP mapping 21 × 3 landmarks → robot joint angles, supervised on paired MoCap + robot data (or via PyRoki differentiable kinematics).

    Pros: Respects robot morphology, can enforce joint limits
    Cons: Requires paired training data or differentiable FK ground truth

    Step 4 — Write LeRobot v2 parquet¶

    import pandas as pd

def write_episode_parquet(
    joint_angles: np.ndarray,   # (T, 14) — 6+1 per arm
    task: str,
    episode_idx: int,
    out_dir: str,
):
    T = len(joint_angles)
    df = pd.DataFrame({
        "observation.state": list(joint_angles),
        "action":            list(joint_angles),  # kinematic — state == action
        "timestamp":         np.arange(T) / 30.0,
        "frame_index":       np.arange(T),
        "episode_index":     np.full(T, episode_idx),
        "index":             np.arange(T),          # global index — fill at merge
        "annotation.human.action.task_description": np.zeros(T, dtype=int),
    })
    path = f"{out_dir}/data/chunk-000/episode_{episode_idx:06d}.parquet"
    df.to_parquet(path, index=False)

    Impediments¶

    Current Blockers

    • Camera extrinsics T_cam_base not yet calibrated for DreamVu's capture rig
    • Unitree G1 hand DOF mapping not confirmed — need to verify against URDF
    • IK approach not chosen (geometric vs. learned) — benchmark needed

    Known Risks

    • MediaPipe landmark jitter at low confidence → noisy joint angle trajectories; will need smoothing
    • multi_hand_world_landmarks z-axis is unreliable under partial occlusion
    • 21 MediaPipe landmarks don't map 1:1 to Unitree G1 finger DOFs — some joints will need interpolation or dropping
    • No wrist 6D orientation in MediaPipe output — must estimate from WRIST + palm landmarks

    Evaluation Protocol¶

    Quantitative¶

    • Joint angle RMSE vs. ground-truth (if paired data available): target < 0.1 rad
    • Trajectory smoothness: mean jerk across extracted episodes
    • Detection rate: % frames with both hands confidently detected (≥ 0.7 confidence)

    Qualitative¶

    • Visualise reprojected joint angles onto Unitree G1 URDF in Isaac Lab
    • Check for self-collisions, joint limit violations, unnatural poses
    • Run open-loop eval (EXP-001 protocol) on extracted trajectories

    Acceptance criteria¶

    • ≥ 90% frames detected per episode
    • No joint limit violations in > 95% of frames
    • Visual inspection: retargeted motion "reads" as the original hand task
