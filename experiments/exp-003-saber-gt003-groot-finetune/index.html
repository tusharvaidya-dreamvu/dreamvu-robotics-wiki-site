    EXP-003: SABER GT003 → GR00T N1.7 Fine-tuning¶

    Owner: Tushar Vaidya
    Start Date: 2026-06-09
    Last Updated: 2026-06-09
    Status: Active

    Goal¶

    Fine-tune NVIDIA GR00T N1.7-3B on the DreamVu GT003 dataset — a proprietary retail hand-motion dataset captured via the SABER pipeline (MediaPipe Hands + HaMeR/HAWOR). Establish whether GR00T N1.7 can learn retail-specific hand-object interaction from ego-view video + tracked joint positions, and produce a deployable checkpoint for Unitree G1 manipulation tasks.

    Hypothesis¶

    GR00T N1.7's diffusion action head, when fine-tuned on GT003's 26,320 retail episodes (~7.15 M training windows), should learn to predict 16-step absolute joint-position chunks from ego-view frames + task text. A 132D action space (27 hand landmarks × 3 axes, minus right_hand_pose) fits within the pretrained model's max_action_dim=132 without any architecture changes.

    Hardware¶

    Field Value
    Server blackwell-6000-4x (34.174.209.221)
    GPUs 4× NVIDIA RTX PRO 6000 Blackwell Server Edition
    VRAM per GPU 96 GB
    Interconnect PCIe only (no NVLink) — see NCCL fix below
    Topology GPU0↔GPU1: PIX · GPU2↔GPU3: PIX · GPU0/1↔GPU2/3: NODE (NUMA)

    Model & Dataset¶

    Field Value
    Base model nvidia/GR00T-N1.7-3B
    Embodiment tag NEW_EMBODIMENT
    Dataset name GT003 (lerobot/gt-003/gt-003-test9 in IBM COS bucket b)
    Episodes (clean) 26,320
    Total frames 7,578,180
    Mean episode length 287.9 frames (9.6 s @ 29.97 fps)
    Action dimensions 132 (138D raw → 6D right_hand_pose dropped)
    Cameras 1 (ego-view, head-mounted, 640×360 H.264)
    Disk ~50 GB (~47 GB video + 3.4 GB parquet + 15 MB meta)
    Task descriptions ~26,426 unique (one per episode, natural language)

    Data Pipeline — SABER¶

    GT003 is collected via the SABER pipeline:

    Retail video (ego-view + third-person)
        ↓
MediaPipe Hands — 21 landmarks per hand (world-space metres, 30 Hz)
        ↓
HaMeR / HAWOR  — dense hand mesh + wrist 6-DoF (fills MediaPipe's wrist orientation gap)
        ↓
LeRobot v2 parquet (138D state / action arrays) + H.264 video
        ↓
GT003 dataset (IBM COS → local /data/gt003-groot)

    See EXP-002 for the MediaPipe → Unitree G1 pipeline and Motion Retargeting theory for the full retargeting framework.

    Training Configuration¶

    Parameter Value
    Steps 20,000
    Global batch size 64 (4 GPUs × 16 samples/GPU)
    DataLoader workers 8
    Training strategy torchrun DDP (--use-ddp, no DeepSpeed)
    Action representation ABSOLUTE / NON_EEF — action = next-frame joint positions
    Action chunk size 16 frames (~0.5 s)
    W&B project gt003-groot / run: gt003-full-finetune
    Modality config examples/gt003/gt003_config.py
    Output dir /checkpoints/gt003-finetune

    State / Action Layout (132D)¶

    Key Dims Offset
    left_hand_pose (3D pos + 3D rot) 6 0–5
    ~~right_hand_pose~~ (dropped) ~~6~~ ~~6–11~~
    left_hand_joints_wrist 3 12–14
    left_hand_joints_thumb 12 15–26
    left_hand_joints_index_finger 12 27–38
    left_hand_joints_middle_finger 12 39–50
    left_hand_joints_ring_finger 12 51–62
    left_hand_joints_pinky_finger 12 63–74
    right_hand_joints_* (5 fingers + wrist) 63 75–137

    right_hand_pose (dims 6–11) is dropped so total = 132D = GR00T-N1.7-3B's max_action_dim. No architecture change needed.

    Docker Setup¶

    # Build base image first
docker build -f docker/Dockerfile -t gr00t .

# Build SABER fine-tuning image
docker build -f docker/Dockerfile.saber -t gr00t-saber .

# Launch fine-tuning (4 GPUs, DDP via torchrun)
docker compose run --rm saber-finetune

# Interactive shell with dreamvu CLI
docker compose run --rm saber

    Key environment variables (all overridable via -e):

    DATASET_PATH=/data/gt003-groot
BASE_MODEL_PATH=nvidia/GR00T-N1.7-3B
OUTPUT_DIR=/checkpoints/gt003-finetune
MAX_STEPS=20000
GLOBAL_BATCH_SIZE=64
NUM_GPUS=4
NCCL_P2P_DISABLE=1      # required on PCIe-only Blackwell (see Bug 6)
NCCL_SHM_DISABLE=1

    The dreamvu CLI is available inside the container for dataset management:

    dreamvu ls --bucket b lerobot/gt-003/
dreamvu sync lerobot/gt-003/gt-003-test9/ /data/gt003-groot/ --bucket b --jobs 8

    Dataset Cleaning (One-Time, Pre-Training)¶

    106 corrupt episodes were removed before training (7 bad video codec + 99 frame count mismatches):

    26,426 raw episodes → remove 106 → 26,320 clean episodes, 7,578,180 frames

    Script: docs/TROUBLESHOOTING_GT003_TRAINING.md → Bug 3 section.

    Also required: patch meta/info.json to add observation.images.ego_view feature entry (Bug 2 fix) — one-time, run on host before first training start.

    Bugs Encountered & Fixed¶

    Bug 1 — ModuleNotFoundError: No module named 'tyro'¶

    Compose .:/workspace bind-mount erases the baked-in venv. Fixed in saber_entrypoint.sh: bootstraps venv into a named Docker volume (saber-venv) on first run (~3 min), cached on subsequent starts (~1 s).

    Bug 2 — AssertionError: Original key observation.images.ego_view not found¶

    meta/info.json was missing the video feature declaration. Fixed by patching info.json on the host to add the observation.images.ego_view entry with shape, codec, fps, and channel metadata.

    Bug 3 — 106 corrupt episodes crash the DataLoader¶

    Episodes with unknown codec or parquet row count > video frame count. Fixed by scanning all episodes with ffprobe + pandas in parallel (32 workers, ~5 min) and removing corrupt files + patching episodes.jsonl and info.json.

    Bug 4 — RuntimeError: module parameters on device cpu (multi-GPU)¶

    Two causes: (a) stale baked entrypoint being run instead of the workspace-mounted version (compose now uses command: ["bash", "/workspace/docker/saber_entrypoint.sh"]); (b) DeepSpeed ZeRO-2 conflicting with torchrun. Fixed by adding --use-ddp flag to bypass DeepSpeed and use native HuggingFace DDP.

    Bug 5 — NCCL rank-to-GPU mapping warning¶

    init_process_group called without device_id. Fixed by calling torch.cuda.set_device(local_rank) before init_process_group and passing device_id=torch.device(f"cuda:{local_rank}").

    Bug 6 — NCCL illegal memory access (P2P over PCIe)¶

    Most impactful. Blackwell SM100 + NCCL direct P2P over PCIe triggers illegal CUDA memory access in the NCCL watchdog. All ranks abort ~9 minutes into startup.

    Fixed by disabling P2P and shared-memory transports:

    NCCL_P2P_DISABLE=1
NCCL_SHM_DISABLE=1
NCCL_SOCKET_NTHREADS=4
NCCL_NSOCKS_PERTHREAD=4
TORCH_NCCL_ASYNC_ERROR_HANDLING=1

    Blackwell PCIe-only topology

    This server has no NVLink. All NCCL collectives route through host RAM. Bandwidth is lower than NVLink but training is stable. GPU utilisation is unaffected during compute — only all-reduce latency increases slightly.

    Full details: docs/TROUBLESHOOTING_GT003_TRAINING.md

    Lessons Learned¶

    • NCCL P2P on Blackwell PCIe-only is broken — must disable NCCL_P2P_DISABLE=1 and NCCL_SHM_DISABLE=1. Not documented in NCCL or PyTorch docs for SM100.
    • Compose bind-mount erases baked venv — always bootstrap venv at container start into a named volume, not into /workspace/.venv directly.
    • DeepSpeed + torchrun = conflict — use --use-ddp for multi-GPU on this setup.
    • right_hand_pose must be dropped — GR00T N1.7 max_action_dim=132; raw 138D state needs slicing in gt003_config.py or training crashes.
    • Dataset cleaning is mandatory — 106/26,426 episodes (~0.4%) were corrupt enough to crash the DataLoader. Always scan before training.

    Next Steps¶

    • Monitor W&B for loss convergence (target: < 0.05 diffusion loss by step 10k)
    • Save checkpoint at step 5k, 10k, 20k
    • Run inference eval on held-out GT003 episodes
    • Test retargeted checkpoint against Unitree G1 URDF in Isaac Lab (EXP-001 protocol)
    • Document final accuracy vs baseline GR00T N1.7 zero-shot
