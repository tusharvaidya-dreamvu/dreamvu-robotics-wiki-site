    SONIC: Supersizing Motion Tracking for Natural Humanoid Whole-Body Control¶

    Authors: Luo*, Yuan*, Wang*, Li* et al. (co-first) · NVIDIA
    arXiv: 2511.07820 · Project: nvlabs.github.io/SONIC
    Date: Nov 2025

    View Slides

    TL;DR¶

    First paper to demonstrate scaling laws for humanoid robot control. Trains a single universal policy on 700 hours / 100M frames of MoCap data using motion tracking as the foundational task. One policy accepts gamepad, VR, video, text, music, and VLA commands — no separate training stages. 100% sim-to-real success on Unitree G1; 95% success on apple-to-plate manipulation with GR00T N1.5.

    Problem¶

    Prior humanoid controllers were small (few million params), reward-engineered per skill, and not scalable. No unified interface existed for heterogeneous control modalities. Motion tracking results were shown only on training data — no downstream deployment.

    Core insight: MoCap-supervised motion tracking is the scalable foundational task — avoids reward engineering, works for any behavior, scales with data like next-token prediction in NLP.

    Architecture¶

    Universal Control Policy¶

    Three MLP encoders all map to a shared latent space via Finite Scalar Quantization (FSQ):

    Encoder Input Use case
    E_r — Robot motion Joint positions/velocities, F_r future frames Tracking recorded robot motion
    E_h — Human SMPL 3D joint positions, F_h future frames Zero-shot human-to-robot transfer
    E_m — Hybrid Sparse head + wrist keypoints + lower-body robot motion VR teleoperation

    Two decoders from the universal token z: - Control decoder → motor commands - Motion decoder → reconstructed motion (auxiliary supervision)

    Training Loss¶

    L = L_PPO + L_recon + L_token + L_cycle

L_token  = ||z_r − z_h||²                    # align robot & human in token space
L_cycle  = ||E_r(D_r(z_h)) − z_r||²          # cycle consistency across embodiments

    L_token + L_cycle are called out as critical — they enable zero-shot human→robot transfer without any retargeting at test time.

    Real-Time Kinematic Planner¶

    Sits above the tracking policy. Generates motion token sequences via Masked Token Prediction (cosine masking schedule) + spring-based root trajectory from gamepad input.

    • <5 ms on laptop · 12 ms on Jetson Orin
    • Replanning every 100 ms

    Scale¶

    Dimension Range tested Best config
    Dataset 0.4M → 7.4M → 100M frames 100M (700 hrs, 170 subjects)
    Model size 1.2M → 42M params 42M
    Compute 8 → 32 → 128 GPUs 128 GPUs, 3 days

    All three axes show monotonic improvement — first empirical scaling law for humanoid motor control.

    Key Results¶

    Benchmark Metric SONIC Best Baseline
    AMASS zero-shot (1,602 traj.) Success rate ~95% ~80% (GMT)
    AMASS zero-shot MPJPE (mm) ~40 ~70 (GMT)
    Sim-to-real (Unitree G1, 50 traj.) Success rate 100% —
    GR00T N1.5 + SONIC (pick-place) Success rate 95% (20 trials) —
    VR teleoperation Wrist error 6 cm (95p: 13.3 cm) —

    Multi-Modal Control¶

    Single policy, no retraining needed for any of these:

    • Gamepad → interactive navigation, speed 0–6 m/s, style variants (drunken, injured, happy, stealth)
    • VR (PICO headset + controllers + ankle trackers) → full-body teleoperation
    • Video → zero-shot motion imitation
    • Text → language-commanded motion style ("walk like a robot")
    • Music → audio-synchronized dancing
    • VLA (GR00T N1.5) → loco-manipulation from vision-language commands

    Relevance to DreamVu¶

    • SONIC's universal token interface is the locomotion/whole-body layer that sits under a VLA like GR00T — directly relevant to DreamVu's humanoid pipeline
    • The L_token + L_cycle losses for cross-embodiment transfer are worth studying for bridging DreamVu's robot data with human demonstrations
    • 100% sim-to-real with Isaac Lab + domain randomization: directly applicable to DreamVu's Isaac Sim setup (EXP-001)
    • VR teleoperation at 6 cm wrist error + 121.9 ms latency sets a practical bar for data collection quality

    Limitations¶

    • No formal safety/compliance treatment for long deployments
    • Sensor noise handling unaddressed
    • VLA task success (95%) is proof-of-concept; broader task distributions remain future work
    • Planner, tokenizer, and policy trained separately — joint training gaps remain
